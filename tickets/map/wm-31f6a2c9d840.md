## Target

Design the root `weave-logs/` directory for shared, unstructured records of longer research, discussion, evidence, and reasoning that support maps and tasks without becoming tickets.

Why: maps and tasks need to retain their current state and conclusions without losing the material that informed them.

## Acceptance direction

The `weave-logs/` directory and its Markdown records are defined clearly enough for teams to store and cite longer evidence without confusing records with tickets or target-tree nodes.

All children are complete and no further children are needed.

Review point: Check that the directory, file-sharing, citation, and short-versus-long record rules are explicit and keep records outside the target tree.

## Decisions so far

- Long records live as shared Markdown files under the root `weave-logs/` directory. They are committed, do not use ticket frontmatter, and are not processed by Waymark. Source: user confirmation.
- A weave log is not a ticket, does not enter the target tree, and does not participate in status, frontier, or acceptance. Source: user confirmation.
- Short facts, observations, and evidence remain inline in a map or task body; longer records use a separate file linked from the relevant body entry. Source: user confirmation.
- Weave logs have no required body structure. Source: user confirmation.
- This map designs the weave-log directory and citation convention; it is a map child of the Execution skills map. Source: user confirmation.

## Not yet specified

- File naming rules under `weave-logs/`.
- The Markdown link convention from tickets to weave logs.

## Out of scope

- Weave logs as target-tree refinement nodes.
