## Target

A person who hits a skill bug, or who wants to say a skill worked well, can send that upstream to `QiYueran-source/weave-your-work` as a labelled issue or a star, after reading the draft.

Why: the skills are used by people who did not write them, and a failure found in use is the only report of it. Without a route it stays in that session and dies there.

## Acceptance direction

All children are complete and no further children are needed.

Review point: `weave-your-work/feedback-me-please/SKILL.md` names the trigger, the repository, the draft-then-send gate, the issue shape, the duplicate check, the star command and the check for an existing star, and what it never sends. The commands it gives resolve against the repository: `gh repo view`, `gh label list`, and the star lookup each return the value the skill says they return, and the run files no test issue.

## Decisions so far

- The skill is named `feedback-me-please`. (user confirmed, 2026-11-10)
- An issue is drafted first and sent only after the person approves; a public issue cannot be recalled. (user confirmed, 2026-11-10)
- The target repository is `QiYueran-source/weave-your-work`. It is public, so the draft is read before it is sent. (verified 2026-11-10 with `gh repo view`: `"visibility":"PUBLIC"`)
- A star is offered, never given without asking. The authenticated account is not currently starred, so the star command has something to change. (verified 2026-11-10: the starred lookup returns 404)
- The issue carries one of the repository's own labels: `bug`, `enhancement`, or `documentation`. (verified 2026-11-10 with `gh label list`)
- It hangs directly under the root map, not under a new category map. (user confirmed, 2026-11-10)

## Out of scope

- Fixing the reported bug. The report goes upstream; the fix is a separate change in that repository.
- Filing on another person's behalf, or filing without their approval.
- A second tracker. GitHub is the one host, the same as the `issue` skill.
