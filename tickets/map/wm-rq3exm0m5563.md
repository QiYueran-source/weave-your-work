## Target

Design the glossary skill so a team keeps one vocabulary while each person writes only their own file: capture a term as JSONL, dedupe and merge into one generated view, constrain later writing with a rules file, and let setup install the pieces.
Why: a shared glossary with many editors conflicts on every change; per-person JSONL sources plus a generated view keep the writing surface small and the reading surface whole.

## Acceptance direction

All child tasks are complete and no further child task is needed: the SKILL.md, the MCP server, the hooks, the rules, and the install step exist; one term written plus a simulated pull shows the term in the generated view; and SKILL.md covers the four moves borrowed from matt's domain-modeling.

## Decisions so far

- Identity: operator first, git `user.name` fallback.
- MCP tools: `glossary_lookup`, `glossary_list`, `glossary_write`, `glossary_merge`; no tool takes another person's file.
- Source: `glossary/<operator>.jsonl`, one term per line with `term`, `definition`, `avoid`, `group`, `created_at`, `updated_at`; these source files are committed and shared.
- Generated view: root `GLOSSARY.md`, ignored and regenerated from `glossary/*.jsonl`, following matt's GLOSSARY-FORMAT.md plus a `_Source_` line per term.
- The install step belongs to this skill, not to setup's design (user confirmed).
- Glossary is an independent skill at `weave-your-work/glossary/`; grill calls it when a term resolves (user confirmed on 2026-11-08). The branch owns the file, fields, merge, and generated view; grill owns the moment.
- The MCP tool interface: `glossary_lookup(term)`, `glossary_list()`, `glossary_write(term, definition, avoid?, group?)`, `glossary_merge()`. No tool writes another operator's file (fixed in this run on 2026-11-08).
- SKILL.md carries the four moves — challenge the term against the glossary, sharpen fuzzy language, test the boundary with a concrete scenario, and check how the project already uses the word — and the write, read, and merge rules. It points at `bundle/rules/rules-glossary.md` for the writing constraints (settled on 2026-11-09).
- Merge reads every `glossary/*.jsonl`, keeps the latest `updated_at` for each term, and writes the view with a `_Source_` line per term. Same-name conflict handling is out of scope for this version (decided in this run on 2026-11-08).
- The view header comes from `glossary/_header.md` when present; otherwise the merge writes a default header. The header is not a term source (decided in this run on 2026-11-08).
- The current 37 terms are migrated to `glossary/frank.jsonl` with `glossary/_header.md`; `GLOSSARY.md` is removed from the index and regenerated by `merge` (decided in this run on 2026-11-08).
- The code lives in `weave-your-work/glossary/bundle/tools/` (`glossary.js`, `server.js`, `post-merge.sh`, `package.json`); the writing rule is `bundle/rules/rules-glossary.md`; the install guide is `bundle/setup.md`; the skill root carries `SKILL.md` and `usage.md` (settled on 2026-11-09).
- The post-merge hook is a shell template at `bundle/tools/post-merge.sh`; the setup guide installs it as `.git/hooks/post-merge` by replacing `@GLOSSARY_SKILL@`. It is recommended, not required; without it, run `merge` after a pull (settled on 2026-11-09).
- Setup and usage are separate: `bundle/setup.md` installs; the skill root's `usage.md` is usage-only and does not repeat the install steps. `SKILL.md` points at both (settled on 2026-11-09).
- The setup guide is cross-platform and instruction-first: Unix and Windows commands where they differ, MCP registration as a JSON instruction, no `install.sh` (settled on 2026-11-09).
- The glossary's own setup copies `bundle/rules/rules-glossary.md` to `.agents/rules/`; the total setup reads every listed skill's `bundle/setup.md` and does not restate or replace the steps. The AGENTS.md prompt belongs to the setup skill (settled on 2026-11-09).
- The 37 definitions were cleaned on 2026-11-08: each is one or two sentences, with no commands, paths, or step lists; the `avoid` lists are split. `GLOSSARY.md` was regenerated from the sources (settled by the cleanup task).
