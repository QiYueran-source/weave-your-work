## Target

Define the operating procedure for creating, exploring, splitting, updating, reviewing, and advancing a map without putting workflow rules into the map body reference.

Why: `body.md` defines what map content means and how it is written; the map skill also needs a separate procedure for how an owner works with that content.

## Acceptance direction

The reference exists under `weave-your-work/map/`, covers the map lifecycle and its hand-offs to explore, split, and review, and a reader can advance a map with it without inventing the sequence.

All children are complete and no further children are needed.

Review point: Check that the procedure names each lifecycle operation, its owner, its hand-off, and the body sections it updates.

## Decisions so far

- Map review writes a Review section for each verdict; status remains the lifecycle state. See [the confirmed discussion](../../testimony/wm-0xrcwvnrcc9k.md).

- The operating procedure is a sibling submap of Map body format under Map skill. It is not part of `body.md` and is not nested under the body-format map. Source: user confirmation.
- The procedure stays deferred: it is not worked on until the map body format, explore, split, and review child skills are settled. Source: user confirmation.
- A new map is discussed before it is split. Grill is the method, not a step of the lifecycle: explore calls it while clearing fog, and split calls it to settle a layer before writing children. Split runs only after the target and the layer are settled. Source: user confirmation.
- Changing a map that has already been split is a change to its children, not a one-file edit. The branches whose meaning depends on the changed sentence are revised in the same run, and a closed child whose verdict was given against the old content is either reopened for a new review or retired and replaced. Source: user confirmation.
- The procedure points at the update skill for the three dispositions and at `frontmatter.md` for who may write what; it states only when a change reaches update and what has to be true before one starts. Source: user confirmation.
- The reference is `weave-your-work/map/procedure.md`, beside `body.md` and `frontmatter.md`. Source: user confirmation.
- A map is reviewed only when it has children and every one is closed. A target with no children that can be checked directly is a task: split prefers a task, and a map whose verdict has no work behind it can close without anything having been done. Source: this map's decision, following the split skill's preference for a task.
- `in_progress` is a loop, not one step. A map splits again each time a layer is settled, and how many splits it takes is not fixed when it starts. The loop ends at a layer of tasks, because a task is a leaf and does not split. Source: user confirmation.
- A change to a map depends on its state: `open` with no children is a plain edit; `in_progress` is a change to its children, with the update skill owning the effect on the nodes that rely on it; `closed` is the update skill's second or third disposition. Source: user confirmation.
- A child reopened while a review is running voids that review. The map stays `in_progress` and is reviewed again once the child closes, because the verdict was being read against a tree that no longer existed. Source: this map's decision.
