## Destination

完成 issue 技能的设计：在远程仓库提 issue、查看和回复、把讨论中形成的决定写回对应 waymark 票，让团队实时交流而不动本地状态。借鉴草案 §六 的分工：远程 issue 用于即时沟通，waymark 是本地唯一状态源。

## Notes

- 类别：沟通类。回答"和人对齐了吗、远程怎么交流"。
- 触发：用户触发，需要和人交流时。
- 交付位置：weave-your-work/issue/（待建）。
- 借鉴来源：.inbox/work-methods/domain-and-conventions.md §六（GitHub/Gitee 用于即时沟通；讨论不复制到本地；只有形成决定才由有权 owner 写回 work item）。

## Decisions so far

- issue 用于远程实时交流，waymark 是本地唯一状态源（草案 §六 方向，未最终确认）。

## Not yet specified

- 支持哪些远程平台（GitHub、Gitee）。
- 提 issue 的流程（标题、正文、标签）。
- 如何把 issue 讨论形成的决定写回 waymark 票。
- 分诊的简化版要不要（needs-triage 那套本期做不做）。
- issue 与 waymark 的关系边界：什么算讨论、什么算决定。
- 讨论内容是否、何时复制到本地。

## Out of scope

- 完整 issue 分诊状态机（如需，后续独立设计）。
- 外部系统连接器、自动同步。
