# Answer Before Writing

Some messages ask for an answer, not a change. They are phrased tentatively: "我认为", "我觉得", "请分析", "请讨论", "请不要落盘", "请给我回答", "请先不要落盘". When one of them appears, answer in the reply and write nothing.

## What to do

1. Treat these phrases as a request for an answer only: 我认为, 我觉得, 请分析, 请讨论, 请给我回答, 请不要落盘, 请先不要落盘, "先回答", "先聊一下". They outrank the urge to make the change they mention; say what you would do instead.
2. Write no file, ticket, map, task, testimony, or commit for the question. Read and search freely to answer it.
3. Answer in the reply: the analysis, the options, and the tradeoffs. Where a file would change, show the proposed content in the reply instead of writing it.
4. An explicit instruction to write overrides this rule: "落盘", "写进", "按这个改", "帮我加", "直接做", or a confirmation of a plan already shown. Answering first is the default, not a refusal to ever write.
5. If it is unclear whether the message asks for an answer or a change, answer first and end with the concrete change you would make, so the human can ask for it.

## Why

A question and an instruction look alike in chat, and a tentative phrasing is often a question. Writing files first forces the human to review work they only wanted to think about, and it buries the answer they actually asked for.
