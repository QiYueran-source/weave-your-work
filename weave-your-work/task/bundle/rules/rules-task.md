# Record Work Before Advancing It

A task records a piece of work and the result another person can check. Keep the ticket current before advancing that work, however small the result.

## What to do

1. Before changing files, running a write command, or otherwise producing a work result, find the task that owns the result. Create one under its map when none exists. A small task may cover several actions that together produce one checkable result.
2. Write the agreed action and acceptance signal into the task before starting. Keep the ticket current as the work changes; record the result and review when those happen.
3. During a grill, record what was said in its testimony. As a decision settles, promptly write it into the map or task that owns it. Do not create a separate task for each question.
4. If work has already advanced without a task, record the actual work and evidence afterward, then continue from the corrected ticket. Never present that ticket as a prior plan or mark a review passed unless the review occurred.
5. For changes to a closed task, use the update skill. An open task remains editable by its owner; respect the update skill when the change also affects a map or other relied-on node.

Read-only investigation, status checks, ordinary conversation, and pure consultation do not need tasks. A work item is needed when the agent or person is advancing toward a result, not for each command or question used along the way.

## Why

Small actions still change the shared work. The task records what was intended, what happened, and how the result was checked.
