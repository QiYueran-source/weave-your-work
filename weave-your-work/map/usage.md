# Map usage

Use `SKILL.md` as the entry point. It routes to the three references and the skills that move a map through its lifecycle.

- Read `body.md` to write or interpret the six map sections, including review history and the single rule for when fog is written.
- Read `placement.md` for dependencies and soft links.
- Read the waymark skill's `fields.md` for fields and write ownership, and `queries.md` for reading the project back.
- Read `procedure.md` to decide the next lifecycle step or understand changes to a split map.
- Read `open-a-map.md` when a map is being opened: a project's first map, or the sibling that replaces a retired one.
- Use `fog-explore`, `split`, or `map-review` for the steps after that. Use `update` when changing a map with children or a closed map.

For installation of the map work-record rule, read `bundle/setup.md`.
