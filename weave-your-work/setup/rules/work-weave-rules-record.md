# Find the Work in the Records Before Editing

Skills record how work was decided. That record only starts when the work has a
place in the tracker, so nothing that changes a file begins before you have
found the one that owns it.

## What to do

1. **Look before you edit.** When a request changes a file, first find the
   record this work belongs to. A read-only check, a status question, and an
   answer given in conversation change nothing, so they look for nothing.

2. **Find it the way this project writes records.** How a project is searched
   is the project's business, not this rule's: read the project's own record
   settings, and use whatever tool it names. The rule does not name one.

3. **Found, work there.** Work the record you found, and say in your answer
   which record it was. Do not open a second record for the same work.

4. **Not found, do not start.** Say that this work has no record in the
   tracker, and leave the decision to the person you are working for: open the
   record that this work should have started from, or settle that this change
   needs no record. Do not open a record yourself to get past this step, and do
   not edit the file while the question is open.

## Why

A change with no record of its own cannot be placed later: a reader sees the
new file and cannot tell which decision asked for it. The skills record a
process; this rule is where the process begins, because a piece of work that
was never looked up was never recorded.
