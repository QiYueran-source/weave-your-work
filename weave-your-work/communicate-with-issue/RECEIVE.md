# Receive a message

A person who has a message for them can do one of three things with it. The list is not a sequence and none of the entries is required: leaving a message alone is a complete response.

Read the issue first. Its front matter names the records it is about; its first record id is the main record, and the main record is where any answer lands.

None of these behaviours closes the issue. The sender closes it.

## Reply in the thread

Answer the ask where it was asked.

**Done when** the comment is on the same issue and the thread carries your answer. A reply is a comment, never a second issue: a new issue on the same subject is a duplicate, and the sender has to close both.

The reply is an answer, not a restatement of the question. If you are declining or asking something back, say that in one sentence first.

## Land what it settled

Write what the message settled on the record it names.

**Done when** the main record carries the answer: the decision written on the spec or ticket that asked for it, and the comment on the issue names the record and one line of what changed. A result that lives only in the thread is lost the next time somebody reads the record.

The record's owner writes it. If the main record belongs to someone else, the landing waits for its owner, and the reply says so.

## Leave it

Say nothing, or reply, and take no other action.

**Done when** the issue still carries the ask and nothing was written on the record. Silence is a legitimate answer; it is not a failure to act, and it is not something to explain.

## What this file does not do

- Close the issue, in any of the three behaviours. Even a landed answer leaves the thread open until the sender closes it.
- Open a new issue to reply, or to ask a follow-up on the same subject. Ask it in the thread.
- Reply to, land, or close a message that is not for this machine. It stays on GitHub as it is.
- Act on a queue entry before the person asks. The queue names open threads; opening the issue is the person's move.
