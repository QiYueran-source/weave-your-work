# Using the glossary tools

The glossary has two front ends over the same sources: an MCP server with four tools, and a CLI. Both read `.work-weave/glossary/*.jsonl` and write only the current operator's file. `GLOSSARY.md` is generated by both; neither edits it by hand.

`<root>` is the project root, the directory with `.waymark/config.toml`. `<runtime>` is that project's glossary runtime at `<root>/.work-weave/runtime/glossary`.

## After install

Run `bundle/setup.md` once. It creates `.work-weave/glossary/`, copies the tools into `.work-weave/runtime/glossary/` and installs their dependencies there, installs the rule, walks you through registering the MCP server, and offers the post-merge hook. The rest of this file assumes it is done.

1. Check the CLI against the project:

   ```bash
   node <runtime>/glossary.js --project <root> list
   ```

   It prints one JSON object per merged term. When the current directory is the project root, `--project` can be left out.

2. Call `glossary_list`. It returns the same terms as the CLI.

3. Write one term, then merge:

   ```text
   glossary_write(term="pricing model", definition="The rules that turn usage into a price.", group="billing")
   glossary_merge()
   ```

   Open `GLOSSARY.md` and check the new term has a `_Source_` line.

## The CLI

```bash
node <runtime>/glossary.js --project <root> list
node <runtime>/glossary.js --project <root> lookup <term>
node <runtime>/glossary.js --project <root> write --term <term> --definition <definition> [--avoid <word>]... [--group <group>]
node <runtime>/glossary.js --project <root> merge
```

- `list` prints every merged term as JSON, one per line.
- `lookup` matches the term exactly, then the part before a parenthetical note. It exits 1 when the term is not found.
- `write` appends one record to `.work-weave/glossary/<operator>.jsonl` and sets both timestamps.
- `merge` rewrites `GLOSSARY.md`; it is the only way to change the view.

The CLI needs no dependencies. The MCP server does.

## The four tools

| Tool | Arguments | Returns |
| --- | --- | --- |
| `glossary_lookup` | `term` | one merged term as JSON, or an error |
| `glossary_list` | none | every merged term as JSON |
| `glossary_write` | `term`, `definition`, `avoid?`, `group?` | the appended record |
| `glossary_merge` | none | the path of the regenerated view |

`glossary_write` has no operator argument. It always writes the current operator's source and never writes another operator's file.

## The files

- `.work-weave/glossary/<operator>.jsonl`: the source. One term per line; committed.
- `.work-weave/glossary/_header.md`: the view header. Not a term source.
- `GLOSSARY.md`: generated and ignored. Never edit it by hand.

## Troubleshooting

- `Cannot find module '@modelcontextprotocol/sdk'`: the MCP server is not installed; run the runtime install in `bundle/setup.md`.
- `Glossary directory not found`: create `.work-weave/glossary/` and add a source as described in `bundle/setup.md`.
- `not found`: the term may carry a parenthetical note; try the part before ` (`.
- `GLOSSARY.md` is stale: run `merge`, or install the recommended post-merge hook from `bundle/setup.md`.
- A write went to the wrong operator: check `.waymark/user.toml` or `git config user.name`. The server resolves the operator at startup, so restart it after a change.
