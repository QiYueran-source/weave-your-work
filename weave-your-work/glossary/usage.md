# Using the glossary tools

The glossary has two front ends over the same sources: an MCP server with four tools, and a CLI. Both read `glossary/*.jsonl` and write only the current operator's file. `GLOSSARY.md` is generated by both; neither edits it by hand.

`<skill>` is the directory that holds this file. `<root>` is the project root, the directory with `.waymark/config.toml`.

## Install and check

1. Run `bundle/setup.md` once; it installs the dependencies, the rule, and the post-merge hook. To install by hand:

   ```bash
   cd <skill>/bundle/tools
   npm install
   ```

2. Check the CLI against the project:

   ```bash
   node <skill>/bundle/tools/glossary.js --project <root> list
   ```

   It prints one JSON object per merged term. When the current directory is the project root, `--project` can be left out.

3. Register the MCP server in the harness's MCP config:

   ```json
   {
     "mcpServers": {
       "glossary": {
         "command": "node",
         "args": ["<skill>/bundle/tools/server.js", "--project", "<root>"]
       }
     }
   }
   ```

   Restart the harness. The four tools should be listed.

4. Call `glossary_list`. It returns the same terms as the CLI.

5. Write one term, then merge:

   ```text
   glossary_write(term="pricing model", definition="The rules that turn usage into a price.", group="billing")
   glossary_merge()
   ```

   Open `GLOSSARY.md` and check the new term has a `_Source_` line.

## The CLI

```bash
node <skill>/bundle/tools/glossary.js --project <root> list
node <skill>/bundle/tools/glossary.js --project <root> lookup <term>
node <skill>/bundle/tools/glossary.js --project <root> write --term <term> --definition <definition> [--avoid <word>]... [--group <group>]
node <skill>/bundle/tools/glossary.js --project <root> merge
```

- `list` prints every merged term as JSON, one per line.
- `lookup` matches the term exactly, then the part before a parenthetical note. It exits 1 when the term is not found.
- `write` appends one record to `glossary/<operator>.jsonl` and sets both timestamps.
- `merge` rewrites `GLOSSARY.md`; it is the only way to change the view.

The CLI needs no dependencies. The MCP server does.

## The four tools

| Tool | Arguments | Returns |
| --- | --- | --- |
| `glossary_lookup` | `term` | one merged term as JSON, or an error |
| `glossary_list` | none | every merged term as JSON |
| `glossary_write` | `term`, `definition`, `avoid?`, `group?` | the appended record |
| `glossary_merge` | none | the path of the regenerated view |

`glossary_write` has no operator argument. It always writes the current operator's source and never writes another operator's file.

## The files

- `glossary/<operator>.jsonl`: the source. One term per line; committed.
- `glossary/_header.md`: the view header. Not a term source.
- `GLOSSARY.md`: generated and ignored. Never edit it by hand.

## Troubleshooting

- `Cannot find module '@modelcontextprotocol/sdk'`: run `npm install` in `<skill>/bundle/tools/`.
- `not found`: the term may carry a parenthetical note; try the part before ` (`.
- `GLOSSARY.md` is stale: run `merge`, or install the post-merge hook with `bundle/setup.md`.
- A write went to the wrong operator: check `.waymark/user.toml` or `git config user.name`. The server resolves the operator at startup, so restart it after a change.
