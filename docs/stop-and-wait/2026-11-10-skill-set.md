# Stop-and-wait: the skill set, read whole

Date: 2026-11-10
Read: the front matter and body of every live map and task, `.agents/rules/*.md`, `.waymark/config.toml`, `GLOSSARY.md`, both ADRs, and the `SKILL.md` of all 19 delivered skills. Every cited file was opened at the cited line.
Skipped: testimony bodies, the worked examples under `use-weave-your-work-examples/`, and `.inbox/`. They record history rather than a current promise; each was opened only where a finding needed its citation.

## F1 — Promise against artifact

- **Class:** Promise against artifact
- **Side A:** `weave-your-work/task/bundle/setup.md:13` and `weave-your-work/map/bundle/setup.md:13` — each says the bundle copies a work-record rule into `.agents/rules/`, and `weave-your-work/task/SKILL.md:8` relies on `.agents/rules/rules-task.md` being there.
- **Side B:** `.agents/rules/` holds ten files, none of them `rules-task.md` or `rules-map.md`; the rules installed are the numbered project rules plus `rules-bundles.md`, `rules-glossary.md`, and `rules-pending-communications.md`.
- **What contradicts:** two skills say their rule is installed in this repository, and it is not. Anyone following `task/SKILL.md:8` opens a path that does not exist, and the work-record rule the bundle exists to deliver is absent from the project that builds it.
- **What would settle it:** run both bundle setups here, or say in each `SKILL.md` that the rule is installed only in a project that ran setup.
- **Likely repair:** `update` on the map that owns the task and map bundles.

## F2 — Rule against practice

- **Class:** Rule against practice
- **Side A:** `weave-your-work/map/body.md:7` — a map body carries six sections in a fixed order, each under the English name the file gives: `Target`, `Acceptance direction`, `Decisions so far`, `Not yet specified`, `Out of scope`, `Review`.
- **Side B:** `tickets/map/wm-8wzzh4hp5evp.md:13` opens with `## Destination` then `## Notes`, and `tickets/map/wm-wjwa9081hse1.md:14` does the same. Neither map has a `Target` section at all.
- **What contradicts:** the reference states one heading set and the two oldest live maps use another. A reviewer reading `map-review` against `body.md` has to fail both maps, and both are load-bearing: one is the entry map, one is the root.
- **What would settle it:** rewrite the two bodies to the six headings, or record in `body.md` that `Destination` and `Notes` are the earlier names and what they map to.
- **Likely repair:** `update` on each map, keeping the text and renaming the sections.

## F3 — Uncovered direction

- **Class:** Uncovered direction
- **Side A:** `tickets/map/wm-wjwa9081hse1.md` `## Acceptance direction` — the set is accepted when every named skill is delivered, installs, and "one end-to-end run over the whole set has been done", that run being one batch over `use-weave-your-work-examples/`.
- **Side B:** the live children of that root are skill maps and their delivery tasks (`tickets/map/wm-ygnttse5hd5k.md`, `tickets/map/wm-0jc0gzrgv7z0.md`, `tickets/map/wm-14tmxq9g2083.md`, `tickets/map/wm-0166kgff304k.md` and the open tasks under `wm-a08fwanmy5q6`). None of their acceptance directions names the whole-set run; each is judged on its own skill.
- **What contradicts:** the root's review point cannot pass on its children, and no child can be found at fault for it. Every child can close while the root stays unpassable, with no ticket left to do the work.
- **What would settle it:** a task under the root that owns the batch, or a line in the root saying which existing child carries it.
- **Likely repair:** `split` on the root for one task, and a decision entry naming it.

## F4 — Rule against practice

- **Class:** Rule against practice
- **Side A:** `weave-your-work/setup/bundle/rules/rules-git.md:7` — "Never commit to the default branch", with the work moving to a branch and a pull request before anything lands.
- **Side B:** this repository's own history. The branch is `main`, and of its 568 commits one arrived through a pull request (`9376a67`, PR #9); the rest, including the three this run follows, are direct commits to `main`.
- **What contradicts:** the skill set ships a git rule its own construction does not follow. A project that installs `setup` gets a rule the reference repository breaks on 567 of its 568 commits, and the reader cannot tell whether the rule is meant or was superseded.
- **What would settle it:** the rule says which branch model it assumes and that a single-owner project may commit to its default branch, or this repository changes how it lands work.
- **Likely repair:** `update` on the setup map, one line narrowing the rule.
